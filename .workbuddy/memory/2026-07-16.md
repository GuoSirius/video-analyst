## pnpm dev 启动失败排查与修复
- 用户报 `pnpm dev` 运行失败。根因两层（均为沙箱环境固有问题，非项目代码 bug）：
  1. **safe-delete 拦截**：`nest start` 启动会删 `dist`，宿主 safe-delete 拦截层把删除转成「移入回收站」，Windows 沙箱不支持回收站 → 报 `Error [safe-delete] 操作失败`。修复：`server/nest-cli.json` 设 `deleteOutDir: false`。
  2. **better-sqlite3 原生二进制缺失**：`pnpm install` 会冲掉预编译二进制，启动报 `Could not locate the bindings file`。修复：进 `node_modules/.pnpm/better-sqlite3@12.10.0/node_modules/better-sqlite3` 执行 `NODE_TLS_REJECT_UNAUTHORIZED=0 prebuild-install -r node` 重拉。
- 验证：`pnpm dev` 现已正常——3000 单监听者、Vite 在 5173、`/api/crawler/tasks` 返回 200 + 种子数据；TSC/vue-tsc 0 issues。
- 一次性 EADDRINUSE 竞态：`nest start --watch -b swc` + `typeCheck:true` 启动有一次双实例抢端口竞态，1 个崩溃、另 1 个正常服务（nest 自愈），属良性噪声。**不要**用 `node --watch`/`concurrently` 包一层——实测每次重编译都反复 EADDRINUSE，更糟。保留原始 dev 脚本。
- 提交 `2139df5`（仅 server/nest-cli.json）。
- 进程树清理坑：`TaskStop` 只停 `concurrently`/`pnpm dev` 父进程；子进程 `node dist/src/main` 命令行不含 "nest.js start"，成孤儿继续占 3000 并锁 db 文件，导致 `git checkout` db 报 `unable to unlink old ... Invalid argument`（同样是 safe-delete 拦截）。彻底清理需按端口 `Get-NetTCPConnection` 定位 owner PID + 递归杀父树。
