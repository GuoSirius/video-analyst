## 整站爬取功能 — 计划与评估
- 用户想在现有「单页 / 列表」采集之上新增「整站爬取」模式：指定站点入口 URL，按规则递归、逐步爬取整站。
- 现状缺口：后端 `processCrawlTask` 是顺序线性分页循环，**无链接发现 / 待访问队列(frontier) / 去重 / 范围过滤**这一层 —— 这是 80% 工作量。
- 方案要点：
  - 新增 `crawl_frontier` 表（url/depth/status/parent_url）做 BFS 队列 + 去重；`crawl_items` 复用。
  - 新增 `processSiteTask`：pop pending URL → fetch → 链接发现+范围过滤+入队 → 命中 itemSelector 则复用既有 parseHtml/详情提取/入库 → 标记 visited → 进度(已访问/上限)。
  - payload 加 `mode:'site'` 与 scope 配置（sameDomain/allowPaths/denyPaths/includeRegex/excludeRegex/maxDepth/maxPages/concurrency/delayMs/linkSelector）。
  - 前端 `CrawlerTasks.vue` 加「整站」模式单选 + 站点配置区块。
- 工作量：一期顺序 BFS ≈ 9.5 人日；并发增强 +1 人日。
- 计划文档：`data/整站爬取实施计划.md`（gitignore 内，不污染仓库）。
- 待用户拍板 4 点：提取模型(仅列表/每页/两者)、并发与否、范围规则粒度、是否复用 detailRules 媒体识别。
