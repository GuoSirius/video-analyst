## 本仓库 git 操作的沙箱坑（重要，可复用）
- 此沙箱下，在未 born 分支（unborn branch）上 `git commit` 会把 commit 变成 dangling（ref 不被写入）；`git branch -f` 与 `git update-ref` 对含斜杠的分支名（如 `feature/whole-site-crawl`）静默失败——因为需要新建 `.git/refs/heads/feature/` 子目录被沙箱拦截。
  - 可靠做法：`git commit-tree <tree> -p <parent> -F <msgfile>` 造 commit 对象，再 `mkdir -p .git/refs/heads/feature && printf '<sha>\n' > .git/refs/heads/feature/whole-site-crawl` 直接写 ref（这些写文件操作需 `dangerouslyDisableSandbox: true`）。
- `npx tsc` 在本沙箱会因 safe-delete（trash 回收站）操作失败，报 `concurrency.lock ... trash operation` 错误。typescript 未本地安装，仅 npx 缓存有。编译后端可用缓存 tsc 或避开 npx；前端 vue-tsc 同此理。
- 本地 main 与 origin/main 原本相差很大（main 停留在早期提交 ed717c5，项目主体文件此前只在暂存区从未提交）。合并后 main 已补齐。
- `git reset --hard HEAD` 在 main 已是真实分支时正常工作，可用来修复「checkout 旧 main 导致工作树缺文件」的脏状态。

## 「5 条任务页面看不到」排查（10:37）
- 现象：用户说之前有 5 条任务、页面看不到了。
- 根因：**后端服务（NestJS, 端口 3000）当时没在运行**。前端 web(5173) 向 `127.0.0.1:3000/api` 发请求处于 SYN_SENT（连不上），任务列表接口拉取失败 → 页面空。
- 数据未丢：DB(`data/video-analyst.db`) 里 `tasks` 表确有 5 条，全部 `type='crawl'`、`status=completed`，payload 含 `mode`（mode 存在 payload JSON 里，非独立列；`tasks` 表结构与 initTables 的 CREATE 完全一致，**无 schema 不匹配**）。`crawl_frontier` 表缺了也无害，启动时会 `CREATE IF NOT EXISTS` 自动补。
- 处理：后台重启后端（`cd server && npm run start`），实测 `GET /api/crawler/tasks/paginated` 返回 total=5、5 条任务名正确。CORS 已开启（main.ts enableCors），跨域无碍。用户刷新页面即可见。
- 教训：页面空白先看后端 3000 是否在跑（netstat 看 LISTENING），再看 DB 是否真有数据。任务数据持久化在 gitignored-tracked 的 DB 文件里，不会因代码/分支操作丢失。

## better-sqlite3 原生模块 Node 版本不匹配（13:53）
- 现象：用户用 Node 26 启动后端报 `ERR_DLOPEN_FAILED`：`better_sqlite3.node was compiled against a different Node.js version using NODE_MODULE_VERSION 127. This version of Node.js requires NODE_MODULE_VERSION 147`。
- 根因：better-sqlite3@12.10.0 当前二进制按 Node 22（ABI 127）编译；用户启动用的是系统 Node 26（ABI 147）。且 **better-sqlite3@12.10.0 没有发布 Node 26 的预编译**（prebuild-install: `No prebuilt binaries found (target=26 runtime=napi arch=x64 platform=win32)`），沙箱内也无法 `node-gyp` 本地编译（无 MSVC 工具链 + TLS/网络受限：`unable to verify the first certificate`）；`pnpm rebuild` 本版本不支持 `--force` 且普通 rebuild 静默跳过不重建。
- 修复：**统一用 Node 22 运行项目**（binary 已匹配，零风险）。验证：Node 22 下 `require('better-sqlite3')` 不报 DLOPEN，Nest 后端 `Nest application successfully started` 全路由正常。
- 防复发：新增 `.nvmrc`（22）+ README 环境要求明确「Node.js 22，勿用 24/26」。提交 763335a（本地，push 仍被挡）。
- 注意：用户机器 3000 端口已被占用（疑为之前 Node 22 正常启动的后端实例），Node 22 下启动若报 EADDRINUSE，先关旧实例或换端口。
